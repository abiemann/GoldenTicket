# Implementation and security audit — September 12, 2026

The full DESIGN is **not implemented**. The new work adds useful parts of M1/M2 and a standalone M0
connectivity experiment. It does not complete camera verification or the game phone companion.
This audit fixes confirmed defects in those additions without changing the product requirements.

## Scope and baseline

- Audited `main` at `f7fd310ec98dc092194ab32496f088c701456ef8`; remote `main` was checked and matched.
- The initial working tree was clean. Six commits since `3c863e3` added pack-away, supply policies,
  the connectivity spike, installation guidance and QR generation.
- Reviewed DESIGN correspondence, source changes and their interaction with the desktop, rules,
  coordinator, replay and encryption. Reviewed the spike's network/certificate/pairing boundaries
  and its browser scripts. The [September 11 audit](AUDIT-2026-09-11.md) remains the baseline review
  for the earlier implementation.
- The baseline suite passed **279 tests**, with none skipped. Passing that suite did not cover the
  defects below. New behavioral browser tests reproduced eight failures before their initial fixes.

## Confirmed findings and corrections

Severity describes the defect before correction. These are fixed in the audit working tree;
outstanding product features are listed separately below.

| Priority | Finding | Correction and coverage |
|---|---|---|
| P1 | Checkpoint readback compared only logical/physical hash strings, allowing inconsistent checkpoint identity, metadata or reconstruction content to be accepted as safe to pack. | Bind the complete immutable checkpoint, its stored metadata, source journal/state versions, profile, pending operation and physical target; replay the source and check lifecycle/target invariants. `PackAwayTests` covers tampering. |
| P1 | A saved rebuild attestation survived a process restart, allowing an old board check to authorize later resume. | Coordinator restore durably invalidates the saved attestation. The rebuilt board requires a fresh check. Restart regression added. |
| P2 | Failed readback could not retry; overlapping continuations raced; a previously verified checkpoint could report safe-to-pack during reconstruction. | Serialize pack-away continuation, support faulted readback retry, use revision-matched commands and restrict success to `PackedAway`. Retry/concurrency/lifecycle regressions added. |
| P2 | Logical checkpoint hashes omitted accepted supply policies and consecutive-pass state. | New `logical-v2` fingerprints include both, retaining read compatibility with authenticated legacy `logical-v1` checkpoints. |
| P1 | The spike treated any RFC1918 address as a trusted Windows Private network, and did not restrict peers to the selected subnet. | Require a Windows Private network profile and validate peer addresses for both HTTPS and certificate bootstrap. Public/unknown profiles fail closed. |
| P1 | The diagnostic report endpoint accepted unbounded retained observations and large request bodies. | Bound request size, connections/write traffic and observation retention. Reports remain diagnostic claims, not trusted proof of device acceptance. |
| P2 | Device sessions remained valid on the server beyond the cookie's twelve-hour lifetime. | Enforce server-side expiry and bound session retention. |
| P1 | Replacing or losing CA material could leave an old leaf in use under the same origin; corrupt trust material could trigger silent replacement. | Validate the leaf's chain against the current CA offline and fail closed on corrupt/incomplete trust state. Bootstrap guidance requires comparison with the laptop's fingerprint. |
| P2 | mDNS could use the wrong outbound interface; static asset resolution depended on launch directory. | Bind multicast transmission to the selected interface and serve assets from the executable's `wwwroot`. |
| P2 | Packed/rebuilding games still offered private reveal and pending-placement prompts; operator acknowledgements could carry into a different decision. | Gate private and placement UI by lifecycle, scope acceptance to the current policy, and clear rebuild attestation when unchecked. Desktop regression tests exercise these transitions. |
| P2 | Resolving certain pauses and resuming a packed AI turn only refreshed the screen, leaving the computer stalled. | Continue eligible computer turns through the normal guarded driver after those transitions. |
| P1 | Taking a face-up locomotive immediately before a refill pause could grant an illegal second card after policy acceptance. | Record the correct interrupted phase for new resolution events and finish the turn. Old resolution events retain their historical replay semantics and hashes. |
| P2 | Reset-disable consent did not consistently last for the match; smaller-market consent could silently bypass reset rules; unsupported saved policies were accepted. | Keep the two consents separate, honor reset-disable through subsequent refills, and reject unknown policy IDs/versions. Setup and legacy-journal regression cases added. |
| P2 | A failed service-worker installation could leave `ready` pending forever and prevent browser-handoff guidance from appearing. | Render guidance first, bound installation and API waits, and release the recheck guard after failures. |
| P2 | Rechecking after pairing was reported as successful reload persistence; stale successes survived disconnection, and one cached HTML file counted as a complete offline shell. | Record reload evidence only from a fresh page's initial session check, clear stale results and check every required shell asset. Prevent duplicate redemption on double taps. |
| P2 | The service worker searched every cache, deleted unrelated caches on activation, and could return HTML for arbitrary failed requests. | Serve only exact allowlisted shell GETs from the current spike cache, preserve unrelated caches and bypass all API/unknown/query/foreign requests. |

The browser fixes have executable tests in
[`shell.test.cjs`](../tests/GoldenTicket.ConnectivitySpike.Tests/shell.test.cjs), using Node's
built-in runner and a controlled browser-API harness. They do not certify an actual browser or phone.
The timeout fix follows the documented behavior of
[`ServiceWorkerContainer.ready`](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerContainer/ready);
cache isolation accounts for the fact that
[`CacheStorage.match`](https://developer.mozilla.org/en-US/docs/Web/API/CacheStorage/match) searches
across caches.

## Validation and practical limits

Final commands, counts, logs and source hashes are recorded in
[`evidence/audit-2026-09-12/validation.md`](evidence/audit-2026-09-12/validation.md).
The NuGet advisory query returned no listed vulnerable direct or transitive packages across eight
projects. This does not establish absence of unknown vulnerabilities or audit the installed OS.

Historical saves that already recorded the old extra-card behavior keep that recorded state on
replay; this update does not retroactively remove cards or rewrite previous turns. New continuations
use the corrected rule path. Full legacy-resolution fingerprints are regression tested.

This audit does not install a CA, change network trust or firewall settings, or claim real-device
PWA acceptance. The host's current Wi-Fi profile is Public; the corrected spike should refuse to
serve it until the owner explicitly designates a trusted network Private. The phone, camera/mount,
GPU, clean-machine installer, real power-loss and operating-system privacy lifecycle gates remain
unverified. See [the device evidence plan](companion-device-evidence.md) and [TODO](../TODO.md).

No release was built or published. Documentation describes partial implementation; it does not
relax the remaining DESIGN requirements.
